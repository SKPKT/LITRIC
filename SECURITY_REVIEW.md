# Keselamatan LITRIC V2

Sasaran aktif ialah Worker sekolah dengan frontend dan API pada origin sama. GitHub hanya menyimpan sumber awam. Tiada Sites identity header atau popup bridge digunakan dalam laluan produksi V2. Konfigurasi lama dikekalkan sebagai rujukan/restore point, bukan server yang diperlukan V2.

- Password: scrypt N=32768, r=8, p=3, salt rawak 128-bit dan derived key 256-bit melalui `@noble/hashes` versi dipin. Library menyediakan implementasi scrypt yang diaudit; konfigurasi ini merujuk panduan scrypt OWASP. Tiada password bootstrap dalam sumber/fixture/bundle/log. Setup terminal tersembunyi, satu kali, tanpa reset akaun sedia ada.
- Sesi: bearer rawak 256-bit hanya dalam memori browser; D1 menyimpan SHA-256 token, bukan token asal. Tempoh mutlak 30 minit, tiada refresh token/localStorage. Refresh halaman memerlukan login semula. Logout dan perubahan password membatalkan sesi server. Password version memutuskan sesi lama. Satu sesi aktif per akaun.
- First login: sesi sementara tidak boleh memanggil API rekod (428). Perubahan password memerlukan password lama dan password baharu berlainan sekurang-kurangnya 12 aksara.
- Rate limit: counter D1 atomik mengikut hash username dan CF connecting IP, masing-masing 10 dan 30 percubaan setiap 15 minit. Mesej login tidak mendedahkan sama ada username wujud. Client tidak menentukan peranan atau sekolah.
- API: auth server dan pemeriksaan role/sekolah/kelas asal digunakan semula. API standalone hanya mendedahkan endpoint untuk empat modul, eksport dan backup berizin. Pelawat tidak menerima data murid. `Origin` browser mesti tepat origin Worker (atau satu origin konfigurasi eksplisit untuk QA berasingan); tiada wildcard CORS atau third-party cookie.
- Frontend: CSP production mengehadkan script/font kepada sumber sendiri. Style inline diperlukan untuk graf React; tiada analytics atau script pihak ketiga. Protected download menggunakan bearer. Data murid tidak disimpan dalam static output.
- Data: schema sedia ada disalin ke migrations D1 terasing, ditambah accounts/sessions/rate limits dan `students.archived_at`. Arkib, status berpindah dan restore tidak memadam summaries/events/aliases. Tiada endpoint delete murid ditambah. Nama serupa tidak digabung automatik.
- Import: tepat ABA6052 apabila kod tersedia. Tanpa kod, hanya nama sekolah tepat yang disokong dan pengesahan manual dibenarkan. ZIP/XLSX mempunyai had saiz. Tahun pelaporan dipelihara dan dipisahkan; pengesahan tahun yang bercanggah dengan sumber ditolak. Duplicate, snapshot, event registry dan overlap disemak sebelum bintang.
- Backend: Worker awam merutekan API ke satu SQLite Durable Object persendirian mengikut sekolah. Objek ini bersiri bagi mengelakkan alokasi hash serentak dan perlumbaan tulis sekolah; semua rekod kekal dalam D1. Bajet CPU Durable Object pada Free mencukupi untuk scrypt; login sebenar akaun sintetik telah diuji tanpa pembelian pelan.
- Setup live: kunci rawak 256-bit disimpan dalam memori CLI sahaja; Cloudflare menerima SHA-256 dan masa tamat 10 minit melalui secret stdin. Endpoint bootstrap melakukan scrypt pada pelayan, menolak kunci salah/tamat, dan tidak menulis ganti GPM sedia ada. CLI memadam dua secret setup selepas selesai. Password hanya dimasukkan dalam terminal tersembunyi dan dihantar melalui HTTPS kepada origin Worker sekolah yang disahkan.
- Ops: token akaun terskop, environment deployment ber-review, sandaran D1 terkawal, inventori R2 dan pemantauan kegagalan. Jangan jalankan bootstrap dalam CI. Free mempunyai kuota; pantau ralat had penggunaan. Semak bilangan login gagal, saiz database, backup/restore dan sesi secara berkala.

Had: ujian dan analisis kod bukan audit penetration bebas. Login live dengan akaun QA sintetik, expiry, logout, rate limit dan empat modul sudah diperiksa. Setup/login GPM oleh pemilik, backup/export produksi, migrasi sebenar, Android fizikal dan cutover belum selesai. Ujian rintis bukan ujian beban; pantau CPU dan trafik sebelum cutover. Service worker/offline cache tidak menyimpan rekod murid. Semua laman pada origin Worker yang sama perlu dipercayai.

Rujukan: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [noble-hashes audits and scrypt](https://github.com/paulmillr/noble-hashes), [Cloudflare Workers limits](https://developers.cloudflare.com/workers/platform/limits/).
